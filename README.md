# المرشد الأكاديمي الذكي – قسم نظم المعلومات

نسخة أولية عاملة من مرشد أكاديمي مؤتمت لبرنامجَي بكالوريوس نظم المعلومات (مسار أمن المعلومات، ومسار إدارة تكنولوجيا المعلومات). يقرأ النظام سجل الطالب ويقارنه بخطته الدراسية، فيقترح مساقات الفصل القادم ويشرح سبب كل اقتراح، ويحسب التقدم والمتبقي حتى التخرج، ويجيب عن أسئلة الطالب اعتمادًا على بياناته فقط.

> **تنبيه:** مشروع تطبيقي غير رسمي، ولا يمثل نظامًا معتمدًا من الجامعة. بيانات الطلبة كلها افتراضية. الخطط الدراسية مستوردة من الوثائق المرفقة وحالتها «مستوردة – بانتظار الاعتماد» حتى يعتمدها القسم من لوحة الإدارة.

---

## 1. التشغيل السريع

المتطلبات: Node.js 20 أو أحدث، وPostgreSQL 14 أو أحدث (أو Docker).

```bash
npm install
cp .env.example .env            # عدّل DATABASE_URL إن لزم
docker compose up -d            # اختياري: قاعدة PostgreSQL جاهزة
npm run setup                   # إنشاء المخطط + الخطط المستوردة + البيانات التجريبية + بناء الواجهة
npm start                       # http://localhost:4000
```

للتطوير، شغّل الأمرين التاليين في نافذتين منفصلتين ثم افتح http://localhost:5173 (يمرَّر `/api` إلى الخادم):

```bash
npm run dev:server
npm run dev:web
```

إذا لم تستخدم Docker فأنشئ القاعدة يدويًا:

```sql
CREATE USER advisor WITH PASSWORD 'advisor';
CREATE DATABASE advisor OWNER advisor;
```

يجب أن تتوفر إضافة `btree_gist` (موجودة ضمن حزمة contrib في PostgreSQL).

### الحسابات التجريبية

| الحساب | كلمة المرور |
|---|---|
| `admin` | `Admin@2026` (أو قيمة `SEED_ADMIN_PASSWORD`) |
| أي رقم جامعي تجريبي من الجدول في القسم 6 | `Demo@2026` |

في وضع `APP_MODE=demo` تظهر قائمة الحسابات في صفحة الدخول للنقر عليها مباشرة.

### نسخة العرض المستقلة

ملف `dist-demo/index.html` (يُبنى بالأمر `npm run build:demo`) هو التطبيق نفسه بمحركه وبياناته، يعمل داخل المتصفح دون خادم أو قاعدة بيانات، والتعديلات فيه مؤقتة في الذاكرة. يصلح للعرض السريع فقط، أما التشغيل الفعلي فيكون بالخادم وPostgreSQL.

### التشغيل عبر GitHub

المشروع جاهز للعمل على GitHub دون أي تغيير في البرنامج. التفاصيل في **[docs/GITHUB.md](docs/GITHUB.md)**:
- **GitHub Pages:** رابط عام لنسخة العرض.
- **GitHub Actions:** الاختبارات الـ90 والبناء تلقائيًا عند كل تعديل.
- **Codespaces:** النظام الكامل مع PostgreSQL في المتصفح.
- **ghcr.io:** صورة Docker جاهزة لخادم الجامعة.

## 2. الاختبارات

```bash
# تحتاج قاعدة اختبار منفصلة (تُمسح بالكامل عند كل تشغيل)
createdb -O advisor advisor_test
npm test
```

- `tests/engine.test.ts`: يغطي السيناريوهات العشرة المطلوبة وحالات إضافية، ويتحقق في كل طالب من الثوابت التالية:
  - لا يُقترح مساق متطلبه السابق غير مستوفى.
  - لا يُحتسب مساق مرتين.
  - الساعات المجتازة منفصلة عن المسجلة والمتبقية.
  - لكل توصية سبب.
  - الحزمة لا تتجاوز حد العبء.
- `tests/api.test.ts`: يختبر المصادقة والقفل بعد المحاولات الخاطئة، وCSRF، وعزل بيانات الطلبة، وصلاحيات الإدارة، وقفل الخطط المعتمدة، ومنع تداخل سنوات الإصدارات، والاستيراد، وسجل العمليات.

النتيجة الحالية: **90 اختبارًا ناجحًا**. يشمل ذلك `tests/production.test.ts` لوضع الإنتاج والاستيراد الجماعي وإلزام تغيير كلمة المرور.

لالتقاط صور شاشة للتحقق البصري:

```bash
node tools/screenshots.mjs http://localhost:4000 ./screenshots
```

## 3. البنية

```
shared/        منطق مشترك بين الخادم والواجهة (TypeScript نقي)
  src/engine.ts      محرك الإرشاد: اختيار الخطة، تحليل المحاولات، الأهلية، الأولويات، التأخر، تدقيق التخرج، تقدير الفصول
  src/assistant.ts   المساعد المقيّد بالبيانات (فهم السؤال بالعربية + إجابة من تقرير المحرك)
  src/seedData.ts    الخطط المستوردة + بيانات الطلبة التجريبية
  seed/plan-*.json   ناتج استيراد ملفات Word
server/        Express + PostgreSQL
  src/db/schema.sql  مخطط القاعدة (الجداول والقيود والمحفزات)
  src/auth.ts        الجلسات، bcrypt، القفل، CSRF، الصلاحيات
  src/routes/        واجهات الطالب والإدارة
  src/services/      تحميل الخطط، تشغيل المحرك، النموذج اللغوي (اختياري)، طبقة تكامل SIS
web/           React + Vite + Tailwind (واجهة عربية RTL متجاوبة)
tools/         أداة استيراد خطط Word، وأداة لقطات الشاشة
tests/         اختبارات المحرك والواجهة البرمجية
docs/source-plans/  ملفات Word الأصلية المرفقة
```

**التقنيات:**
- الواجهة: React 18 وTypeScript، مع Tailwind CSS.
- الخادم: Express 5 وTypeScript.
- قاعدة البيانات: PostgreSQL.
- الحماية وفحص المدخلات: bcrypt، وzod، وhelmet، وrate-limit.

### مبادئ المحرك
1. **قواعد قابلة للتفسير:** كل توصية تحمل قائمة أسباب، مثل: متطلب سابق مستوفى، مساق راسب يجب إعادته، متأخر عن الخطة الاسترشادية، يفتح عددًا من المساقات اللاحقة، أو من فئة متأخرة.
2. **الأهلية من السجل الفعلي لا من السنة الدراسية:** المساق متاح فقط إذا اجتاز الطالب كل متطلباته السابقة. إذا كان المتطلب مسجلًا حاليًا يظهر المساق «مشروطًا» بوضوح، ولا يُعرض على أنه متاح.
3. **لا اختراع:**
   - علامة النجاح، وسياسة الإعادة، والحد الأقصى للعبء، وحد معدل التخرج غير مذكورة في الوثائق، فتبقى «غير مضبوطة» ويظهر للطالب تنبيه.
   - في غياب حد العبء الرسمي، يُستخدم عبء الخطة الاسترشادية للفصل المعني ويوصف بأنه «مرجعي».
4. **تقدير التخرج مشروط:** يحاكي المحرك الفصول القادمة ويسرد الافتراضات التي بنى عليها التقدير.
5. **حالات التخرج الثلاث منفصلة:**
   - «متوقع التخرج»: كل المتبقي مسجل حاليًا.
   - «مستوفٍ للمتطلبات»: حسب بيانات النظام، دون قرار رسمي.
   - «خريج»: فقط إذا ثبت ذلك في سجل الجامعة.

### المساعد الذكي والخصوصية
- يعمل افتراضيًا بمحرك محلي لا يرسل أي بيانات خارج النظام. يفهم الأسئلة العربية، بما فيها صيغ عامية شائعة، ويتعرف على المساقات بالاسم أو الرمز.
- يمكن تفعيل نموذج لغوي خارجي لصياغة الإجابات عبر `LLM_PROVIDER=anthropic` و`LLM_API_KEY` و`LLM_MODEL` مع القاعدة `llmEnabled`. يُرسل له حينها سياق مجهّل فقط، بلا اسم ولا رقم جامعي.
- إذا ذكرت إجابة النموذج رمز مساق غير موجود في الخطة تُرفض، ويُعاد للطالب جواب المحرك المحلي.

## 4. قاعدة البيانات

الجداول المطلوبة كلها موجودة، إضافة إلى جداول مساندة:

| الجدول المطلوب | الجدول في المخطط |
|---|---|
| Students | `students` (+ `users` للحسابات و`sessions`) |
| Programs / Tracks | `programs`، `tracks` |
| StudyPlans / PlanVersions | `study_plans`، `plan_versions` |
| Courses / PlanCourses | `courses`، `plan_courses` (+ `plan_categories`، `guiding_slots`) |
| CoursePrerequisites / CourseCorequisites | `course_prerequisites`، `course_corequisites` (لكل إصدار خطة) |
| StudentCourseRecords / CourseRegistrations | `student_course_records`، `course_registrations` |
| AcademicTerms | `academic_terms` (+ `course_offerings`) |
| AdvisingRecommendations | `advising_recommendations` (لقطة يومية للتوصيات) |
| GraduationRequirements | `graduation_requirements` (+ `student_requirement_status`) |
| AdvisingRules | `advising_rules` |
| AuditLogs | `audit_logs` (+ `error_logs`) |
| – | `course_equivalences` لمعادلة مساقات الخطط السابقة |

**قيود تمنع التناقض:**
- رمز المساق 8 أرقام.
- فصل حالي واحد فقط.
- لا تكرار لسجل الطالب في المساق والفصل نفسيهما.
- المتطلب السابق لا يكون المساق نفسه، ويجب أن يكون ضمن الخطة.
- لا تتداخل نطاقات سنوات الالتحاق بين إصدارات الخطة الفعّالة لنفس المسار (قيد `EXCLUDE`).

**حماية سجلات الطلبة السابقين:** محفّز في قاعدة البيانات يمنع تعديل محتوى خطة «معتمدة». لتحديث خطة:
1. انسخها كإصدار جديد بنطاق سنوات جديد.
2. عدّل النسخة.
3. اعتمدها.

الطلبة السابقون يبقون على إصدارهم. ويمكن إسناد خطة صراحةً لطالب منقول، مع جدول معادلات للمساقات.

## 5. ملاحظات على البيانات المستوردة (يجب أن يراجعها القسم)

استوردت الأداة `tools/import_docx_plans.py` الملفات الأربعة آليًا. هذه نتائج الفحص:

1. **مجموع الفئات 136 ساعة والخطة تنص على 133:** يتطابق الرقمان إذا لم يُحتسب «إنجليزي استدراكي» (3 ساعات). لذلك يُعامل متطلبًا إلزاميًا غير محتسب، وهذا قابل للتعديل من «فئات المتطلبات».
2. **الخطة الاسترشادية توزّع 124 ساعة محتسبة فقط:** ينقصها 3 ساعات من متطلبات الجامعة الإجبارية (عادة «اللغة الإنجليزية 2»)، و6 ساعات من اختياري التخصص. المحرك يجدول الفرق تلقائيًا ويبرزه للطالب في نهاية الخطة.
3. **متطلب «اللغة الإنجليزية (2)» 15200112:** خطة أمن المعلومات تشترط له 15200106، وخطة إدارة تكنولوجيا المعلومات لا تذكر أي متطلب. حُفظ كما ورد في كل وثيقة، ويظهر تنبيه بذلك في لوحة الإدارة.
4. **التدريب الميداني:** ورد في الخطة الاسترشادية بـ0 ساعة، فسُجّل متطلب تخرج غير ساعي يُوثّق من لوحة الإدارة. تفاصيله غير مذكورة.
5. **سنة بدء تطبيق الخطط غير مذكورة:** ضُبطت مؤقتًا على 2021، ويجب تأكيدها.
6. **ملفا الخطة الاسترشادية للمسارين متطابقان في المحتوى**، لأن خانات الاختياري فيهما عامة.

## 7. النشر على خوادم الجامعة

الدليل الكامل لمركز تكنولوجيا المعلومات في **[deploy/DEPLOY.md](deploy/DEPLOY.md)**. يشمل:
- التركيب بطريقتين: Docker، أو بدونه مع systemd.
- إعداد Nginx وHTTPS.
- النسخ الاحتياطي والاستعادة.
- التحديث إلى إصدار جديد، وقائمة تحقق للأمن والخصوصية.

| الملف | الغرض |
|---|---|
| `deploy/Dockerfile`، `deploy/docker-compose.prod.yml` | التشغيل بالحاويات (التطبيق + PostgreSQL) |
| `deploy/env.production.example` | قالب إعدادات الإنتاج |
| `deploy/nginx/advisor.ptuk.edu.ps.conf` | الوكيل العكسي وHTTPS على النطاق الفرعي |
| `deploy/systemd/smart-advisor.service` | خدمة دائمة دون Docker |
| `deploy/backup.sh` | نسخ احتياطي يومي مع الاحتفاظ بآخر 30 نسخة |
| `deploy/department-page-snippet.html` | بطاقة ورابط «المرشد الأكاديمي» لصفحة القسم على موقع الجامعة |

### ما يتغير في وضع الإنتاج (`APP_MODE=production`)
- `npm run db:init:prod` يهيئ القاعدة بالخطتين المستوردتين فقط، **دون طلبة أو خطط تجريبية**.
- يرفض النظام التهيئة الأولى دون `SEED_ADMIN_PASSWORD` قوية (10 أحرف على الأقل).
- لا تظهر الحسابات التجريبية في صفحة الدخول.
- لا تُمنح حالة «خريج» يدويًا.

### إدخال البيانات الحقيقية
من «التكامل» في لوحة الإدارة تُستورد ثلاثة ملفات CSV بالترتيب:
1. **الطلبة:** `university_id,name_ar,track,enrollment_year,academic_year_level,gpa,status,field_training`. يُنشأ لكل طالب جديد حساب بكلمة مرور أولية عشوائية، وتُنزَّل كلمات المرور في ملف.
2. **السجل الأكاديمي:** `university_id,course_code,term_code,status,grade`.
3. **التسجيل الحالي:** `university_id,course_code,term_code`.

كل ملف يُفحص قبل الاستيراد، ويقبل الترميز UTF-8 مع علامة BOM التي يضيفها Excel، والحقول بين علامات التنصيص.

يُلزَم الطالب بتغيير كلمة المرور الأولية عند أول دخول. وتعيد الإدارة هذا الإلزام عند إعادة تعيين كلمة مرور أي طالب.

### المراحل اللاحقة
- **الدخول بحساب الجامعة:** ربط تسجيل الدخول بحسابات Microsoft 365 الجامعية.
- **الربط مع Edugate:** عبر واجهة رسمية، والطبقة جاهزة في `server/src/services/sis.ts`.

التوصيات للطالب الحقيقي تُوصف بأنها «مبدئية» ما لم تكن خطته «معتمدة» وسجله «مكتملًا».
